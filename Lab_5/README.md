# Лабораторная работа 5: Снифер пакетов (без разбора заголовков)

## Задание
> Написать снифер — программу, перехватывающую сетевые пакеты, проходящие через сетевой интерфейс. Заголовки пакетов не разбирать.

## Структура
```text
Lab_5/
├── go.mod
├── README.md
└── main.go   # снифер (~120 строк, только стандартная библиотека)
```

## Запуск
Raw-сокеты в Windows доступны **только администратору**, поэтому терминал нужно открыть «От имени администратора»:
```powershell
cd "D:\Сетевые приложения\Lab_5"
go run .
```
Чтобы пакеты точно пошли, откройте в браузере любой сайт или выполните `ping 8.8.8.8` в соседнем окне.

> Если пакеты не появляются — разрешите программу в брандмауэре Windows (при первом запуске обычно всплывает окно).

## Как это работает

Обычный сокет (TCP/UDP) получает только данные, адресованные ему — ОС сама снимает заголовки IP/TCP/UDP и отдаёт программе «чистое» содержимое. Снифер устроен иначе:

1. **RAW-сокет** — `socket(AF_INET, SOCK_RAW, IPPROTO_IP)`. Такой сокет получает пакет **целиком, вместе с IP-заголовком**, ОС ничего не снимает.
2. **bind на IP сетевой карты** — Windows требует привязать raw-сокет к конкретному интерфейсу. Свой IP определяем через «фиктивное» UDP-подключение к 8.8.8.8 (данные при этом не отправляются).
3. **`WSAIoctl(SIO_RCVALL, 1)`** — ключевой шаг. Переводит интерфейс в режим, когда сокету отдаются **все** IP-пакеты, проходящие через карту (входящие и исходящие), а не только адресованные ему. Это аналог promiscuous mode.
4. **Цикл `WSARecv`** — каждый вызов возвращает один IP-пакет. Мы выводим номер, время, длину и первые 64 байта в виде hex-дампа (как в Wireshark: смещение | байты | ASCII). Заголовки не парсим.
5. При выходе выключаем режим (`SIO_RCVALL, 0`) и закрываем сокет.

### Как читать вывод
```
#1  19:30:12.481  длина: 52 байт
  0000  45 00 00 34 5c 2f 40 00 80 06 00 00 c0 a8 01 05  |E..4\/@.........|
  0010  8c 52 79 03 ...
```
Хотя мы ничего не разбираем, в дампе видно структуру IP-пакета:
- `45` — первый байт: версия IPv4 (`4`) и длина заголовка 5×4 = 20 байт;
- байт по смещению 9 — протокол: `06` = TCP, `11` = UDP, `01` = ICMP;
- байты 12–15 — IP отправителя, 16–19 — IP получателя (`c0 a8 01 05` = 192.168.1.5);
- после 20 байт IP-заголовка идёт TCP/UDP-заголовок, а за ним данные (у HTTP иногда видно текст в правой колонке).

### Ограничения
- Видны только IP-пакеты (уровень 3). Ethernet-заголовки (MAC-адреса) через `SIO_RCVALL` не приходят — для этого нужен драйвер Npcap/WinPcap.
- Ловится трафик только одного интерфейса — того, к которому сделан bind.
- Нужны права администратора.

## Контрольные вопросы (кратко)
- **Что такое снифер?** Программа перехвата и анализа сетевого трафика.
- **Чем raw-сокет отличается от обычного?** Получает пакет с заголовками сетевого уровня, а не только полезные данные.
- **Что такое promiscuous mode?** Режим сетевой карты, при котором она принимает все кадры в сегменте, а не только адресованные её MAC.
- **Зачем права администратора?** Raw-сокеты позволяют читать чужой трафик и подделывать пакеты, поэтому ОС их ограничивает.
